### Fixed (dev34 — shell frame overflow)

- New Platform Concept **`UI/PlatformComponents/TickerGuard.cs`** — the only seam an `IDispatcherTimer.Tick` subscription or a MAUI `Animation.Commit` callback may run through. It swallows whatever the body throws, logs the FIRST failure per ticker name to `crash.log` + `interaction-log.txt` **with the live stack** (the exception's own stack is empty when native code threw, which is exactly what made these deaths unreadable), and parks a ticker that fails 30 times running (`timer.Stop()`, or `ShouldStop(ticker)` in the repeat condition for callbacks that own no timer, so a broken 60 fps loop cannot become an exception storm in an app that lives in the tray for days).
- **Why it must exist (proven from crash dumps, `docs/postmoterm/published-layout-dispatcher-failfast-2026-10-28.md`)**: WinUI raises dispatcher-timer ticks through its own delegate adapter, so an exception leaving that adapter is **stowed** by combase and turned into `RoFailFastWithErrorContextInternal2` → `0xC000027B` — an instant process kill that **never consults `Application.UnhandledException`**, the hook that saves every other XAML fault. Two dumps captured the identical chain with *different* inner errors (`0x80004002`, `0x80004005`), which is the proof that the escape itself is fatal rather than one specific throw.
- All **ten** managed per-frame loops routed through it: `ShimmerBox`, `EnrichmentShimmerOverlay`, `NewRibbonBadge`, `ChromeValueLabel`, `LastScanStatus`, the dashboard text timer, the dashboard slide's `finished:` callback, `PipelineRadar`'s frame ticker, and `SourceMorphTransition`'s cleanup + refresh timers. Three of them took their handler signature down to parameterless (`OnSharedTickerTick`/`OnCleanupTick`/`OnRefreshTick` never used `sender`/`e`).
- The WinUI `UnhandledException` handler now also records the **live** thread stack with the report, for the faults that *do* reach it.
- Binding **rule 6** added to `.repertoire/.steering/v3/animation-safety.md` ("No tick or animation callback may throw into WinUI"), with the dump evidence inline so the next reader does not re-derive it, and a `docs/UNITS.md` row for the new unit.
- **`ParserTests.TestTickerCallbacksAreGuarded`** scans every source directory and fails if any `.Tick +=` exists outside `TickerGuard`, carrying a `guarded >= 8` floor so it cannot pass by matching nothing (the vacuous-lint mistake this suite already documents once). ParserTests **453/0** (+3).


### Added (dev61 — the crash hunt's instruments stay in the tree)
- **`Platforms/Windows/Program.cs` logs a birth certificate** on every launch — `pid`, parent pid (via `NtQueryInformationProcess`), channel, version, `toastActivation=`, redirect key — before any WinUI/singleton code runs, and every `startup-debug.log` line now carries `pid:` while every `interaction-log.txt` line carries `| pid= |`. Two channels writing into one log with nothing but timestamps to separate them made a WER dump whose pid matched no launched instance un-debuggable; the first such dump this session (`16864`) is now attributable in one grep.

Its old filter — `InvalidCastException / COMException / EntryPointNotFoundException` — was hiding the very failure being hunted: the fatal `0x80004005` is what a *plain* `System.Exception` marshals to, so the probe saw nothing in the runs that died. - **`docs/postmoterm/published-layout-dispatcher-failfast-2026-10-28.md`** — ten dumps parsed by hand, all the same instruction, symbolicated to `CXcpDispatcher::MessageTimerCallback` (WinUI's own dispatcher pump, not a callback we own), inner errors `E_NOINTERFACE`/`E_FAIL`.
