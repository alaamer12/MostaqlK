# Single Ground Architectural Blueprint & Implementation Plan
**MostaqlK Cross-Platform Architecture (.NET MAUI V1 — Windows & Mobile)**

---

## 1. Executive Summary & Authoritative Audit Sources

This document defines the authoritative architectural blueprint and refactoring plan for **MostaqlK**. Based on the **Single Ground Principle** (detailed in `bugfree.txt`), C# 12 / .NET 10 MAUI standards, and comprehensive static and manual codebase audits, this blueprint eliminates **layer contamination**, **duplicated micro-decisions**, and **platform drift** between Windows desktop and Mobile (Android / iOS).

### Primary Audit Sources & Findings Reports
This blueprint incorporates and synthesizes all findings from the two dedicated architectural audits conducted on the codebase:
1. **Automated AST & Regex Scan Report**: [`.repertoire/agents/script-violation-scanner.md`](../.repertoire/agents/script-violation-scanner.md)
   - Generated by Python AST scanner (`scratch/scan_violations.py`) analyzing all 211 C# and XAML files.
   - Identified 148 initial candidate sites and isolated 14 high-impact Single Ground violations across presentation slicing, formatting bypasses, and duplicated micro-decisions.
2. **Manual Deep Architectural Swipe Report**: [`.repertoire/agents/codebase-deep-swipe-auditor.md`](../.repertoire/agents/codebase-deep-swipe-auditor.md)
   - Comprehensive layer-by-layer audit examining data flow, database lifecycle, inverted dependencies, background services, cross-platform parity gaps, and silent runtime binding failures.

### The Core Insight
Bugs in cross-platform systems rarely stem from simple code duplication; they arise from **duplicated decisions (micro-decisions) without an authoritative source of truth**. When Data Ingestion, ViewModels, and UI Layouts independently invent fallback values, string truncation limits, Arabic pluralization, or relative time calculation:
1. Every component appears locally correct and passes isolated tests.
2. The system as a whole drifts into global inconsistency.
3. Database storage becomes polluted with temporary presentation text, creating unnecessary lock contention and write cycles.

**The Golden Rule:** *Every business decision, linguistic rule, validation constraint, and display policy must have exactly one authoritative Single Ground.*

## 2. Layer Contamination & Responsibility Boundaries

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                             AUTHORITY MATRIX                                │
├──────────────────────────┬───────────────────────┬──────────────────────────┤
│ Decision Type            │ Authoritative Ground  │ C# Mechanism             │
├──────────────────────────┼───────────────────────┼──────────────────────────┤
│ Domain Rules & Grammar   │ Core/Domain/ &        │ Pure static formatters,  │
│ (Arabic plural, initials)│ Core/Formatting/      │ Value Objects (records)  │
├──────────────────────────┼───────────────────────┼──────────────────────────┤
│ Ingestion & Storage      │ Infrastructure/       │ Raw DTOs, UTC timestamps │
│ (Raw facts, zero UI text)│                       │ SQLite / FTS5 tables     │
├──────────────────────────┼───────────────────────┼──────────────────────────┤
│ State & Presentation     │ Features/*/ViewModels │ Reactive properties,     │
│ Transformation           │                       │ calls to Core/Formatting │
├──────────────────────────┼───────────────────────┼──────────────────────────┤
│ Visuals & Layout Styling │ UI/DesignSystem/ &    │ AppThemeBinding, XAML    │
│ (Tokens, View Barrels)   │ View Barrels          │ Styles, UNITS.md units   │
├──────────────────────────┼───────────────────────┼──────────────────────────┤
│ Platform Divergence      │ Core/Platform/ &      │ PlatformSelect.For<T>(), │
│                          │ Platforms/            │ PlatformCapability<T>    │
└──────────────────────────┴───────────────────────┴──────────────────────────┘
```

### 1. Ingestion & Storage Layer (`Infrastructure/`)
- **Strict Role**: Ingest raw HTML/API payloads and store canonical raw facts in SQLite.
- **Prohibitions**:
  - ❌ MUST NOT generate or store localized UI presentation strings (`publish_time_text`, `proposal_count_text`).
  - ❌ MUST NOT use periodic background services (`PublishedTimeUpdateService`) to rewrite UI strings into SQLite.
  - ❌ MUST NOT silently mask missing fields with arbitrary UI fallbacks (`?? "غير محدد"`, `?? ""`).
  - ❌ MUST NOT apply ad-hoc relative time parsing regex during scraping.

### 2. Domain & Rules Layer (`Core/`) — The Single Ground
- **Strict Role**: Pure, platform-agnostic business logic, Arabic linguistic engines, and immutable domain models.
- **Rules**:
  - ✅ Independent of UI frameworks (MAUI XAML) and Database implementations.
  - ✅ Houses canonical engines: `ArabicRelativeTime`, `ArabicProposalParser`, `ArabicNameFormatter`, `BudgetFormatter`, `TextTruncator`, `PipelineTelemetryFormatter`.
  - ❌ MUST NOT depend on `Infrastructure/` (strict clean architecture inversion).

### 3. Presentation Layer (`Features/*/ViewModels`)
- **Strict Role**: Expose state and transform raw domain facts into bindable properties by invoking `Core/Formatting/`.
- **Prohibitions**:
  - ❌ MUST NOT slice strings or strip Arabic prefixes manually (e.g. `ClientInitials` stripping "ال").
  - ❌ MUST NOT invent ad-hoc pluralization (`$"{count} عرض"`).
  - ❌ MUST NOT hardcode raw hex colors or duplicate status badge switch expressions.

### 4. Layouts & Design System (`UI/` & `Features/*/Views/Layouts`)
- **Strict Role**: Pure visual structure, gesture handlers, and responsive layout swapping via View Barrels.
- **Prohibitions**:
  - ❌ Zero business or formatting logic in XAML or code-behind.
  - ❌ No inline `StringFormat` with broken Arabic grammar (`StringFormat='{0} أيام'`).

## 4. Comprehensive Audit Findings & Violations Inventory

| ID | Location | Layer Violation | Root Cause / Impact | Single Ground Remedy |
|---|---|---|---|---|
| **V-01** | `Services/PublishedTimeUpdateService.cs`, `Infrastructure/Database/ProjectRepository.cs` | Data Layer Contamination | Persisting temporal UI strings (`publish_time_text`) in SQLite and waking up every 60s to rewrite them. | Drop columns from DB; calculate on-demand via `ArabicRelativeTime.Since()`; delete `PublishedTimeUpdateService`. |
| **V-02** | `Core/Formatting/ArabicProposalParser.cs` | Inverted Dependency | `Core` directly references `Infrastructure.Http.Parsers.StructuralExtractor`. | Move `NormalizeLabel` and `ToAsciiDigits` to `Core/Utilities/StringNormalization.cs`. |
| **V-03** | `Features/Projects/ViewModels/ProjectCardViewModel.cs` (lines 98-135) | Presentation Contamination | Hand-rolled "ال" stripping for Arabic initials in ViewModel. | Extract to `Core/Formatting/ArabicNameFormatter.cs`. |
| **V-04** | `Features/Projects/ViewModels/ProjectCardViewModel.cs` (lines 152-154) | Presentation Contamination | Ad-hoc proposal pluralization `$"{ProposalCount} عرض"` producing broken Arabic. | Centralize pluralization into `Core/Formatting/ArabicProposalParser.cs`. |
| **V-05** | `Features/Projects/ViewModels/ProjectCardViewModel.cs` vs `ProjectDetailsWindowsLayout.xaml` | Duplicated Micro-Decision | Three different formatters for delivery days (`ArabicRelativeTime.Days`, `"{days} يوما"`, `"{0} أيام"`). | Consolidate all duration formatting to `ArabicRelativeTime.Days(days)`. |
| **V-06** | `Features/Projects/Views/Layouts/ProjectDetailsWindowsLayout.xaml` (line 147) | Bypassing Formatter | Detail views bind directly to raw unformatted `Details.Budget` string instead of formatted SAR/USD. | Expose formatted `Budget` via `BudgetFormatter.Format()` in `ProjectDetailsViewModel`. |
| **V-07** | `ProjectCardViewModel.cs` (184-211) & `ProjectDetailsViewModel.cs` (166-191) | Duplicated Micro-Decision | Duplicated status switch statements and raw hex colors (`#ECFDF5`, `#FEF2F2`, `#FFFBEB`). | Centralize badge visual styling in `UI/DesignSystem/Badges/EnrichmentBadgeStyle.cs`. |
| **V-08** | `Infrastructure/Notifications/WinAppSdkVariation.Windows.cs` & `WinRtVariation.Windows.cs` | Duplicated Micro-Decision | Duplicated `.Substring(0, 197) + "..."` truncation logic. | Centralize in `Core/Formatting/TextTruncator.Truncate()`. |
| **V-09** | `PipelineRadar.xaml.cs` & `PipelineDashboardPanel.xaml.cs` | Duplicated Micro-Decision | Duplicated worker status text (`StatusText`) and seconds formatters (`Format(seconds)`). | Move to `Core/Formatting/PipelineTelemetryFormatter.cs`. |
| **V-10** | `Infrastructure/Http/Parsers/ListingParser.cs` vs `DetailParser.cs` | Data Layer Inconsistency | `DetailParser` parses Arabic duals as `0` instead of `2` due to `ParseLeadingInt`. | Standardize on `ArabicRelativeTime.ParseRelativeNumber()`. |
| **V-11** | `Features/Notifications/Views/RecentNotificationsFlyout.xaml` (line 97) | Silent Binding Failure | XAML binds `{Binding PostedRelative}` on raw `ProjectSummary` DTOs where property does not exist. | Introduce `NotificationItemViewModel` exposing `PostedRelative`. |
| **V-12** | `Features/Projects/Views/Layouts/ProjectCardMobileLayout.xaml` | Feature Parity Gap | Missing skills tag row mandated by Card Type 3 in Mobile Architecture Specification. | Add flex-wrap skills container to `ProjectCardMobileLayout.xaml`. |
| **V-13** | `Features/Projects/Views/Layouts/ProjectDetailsMobileLayout.xaml` | Feature Parity Gap | Missing owner stats card present on desktop layout. | Add mobile-adapted owner statistics card to mobile details layout. |
| **V-14** | `Infrastructure/Database/ProjectRepository.cs` (lines 799-831) | Database N+1 Query | `GetAllDetailsAsync` executes 2 separate queries per project row for skills and assets. | Batch fetch related entities using single batched query or JOIN. |

## 6. Implementation Action Plan & Phased Roadmap

### Phase 1: Core Foundation & Inverted Dependency Cleanup
1. **Create `Core/Utilities/StringNormalization.cs`**:
   - Move `NormalizeLabel`, `ToAsciiDigits`, and diacritic stripping out of `Infrastructure/Http/Parsers/StructuralExtractor.cs`.
   - Ensure `Core/` has zero project references to `Infrastructure/`.
2. **Implement Core Formatters in `Core/Formatting/`**:
   - `ArabicNameFormatter.cs`: Pure initial extraction with "ال" prefix stripping.
   - `ArabicProposalParser.cs`: Canonical pluralization rules (`عرض واحد`, `عرضان`, `X عروض`, `X عرضاً`).
   - `TextTruncator.cs`: Safe truncation with word-boundary awareness and ellipsis.
   - `PipelineTelemetryFormatter.cs`: Centralized worker status text and elapsed seconds.
   - Extend `ArabicRelativeTime.cs` with `ParseRelativeNumber(string text)` to unify scraper time extraction.
3. **Add Unit Tests in `MostaqlK.UITests` / Test Suite**:
   - Test all Arabic grammar cases, duals, plurals, name prefixes, and duration formats.

### Phase 2: SQLite Schema Cleanup & Background Service Removal
1. **Purge Presentation Columns from SQLite**:
   - Update `Infrastructure/Database/ProjectRepository.cs` schema creation: remove `publish_time_text`, `publish_time_number`, `proposal_count_text`.
   - Store only raw `discovered_at` (UTC ISO-8601 string) and `proposal_count` (INTEGER).
2. **Remove `Services/PublishedTimeUpdateService.cs`**:
   - Delete the service and remove its hosted background worker registration in `MauiProgram.cs`.
   - ViewModels will compute relative time dynamically on-demand.
3. **Fix N+1 Query in `ProjectRepository.GetAllDetailsAsync`**:
   - Refactor to batch-load skills and attachments in a single query.

### Phase 3: ViewModel Refactoring & Design System Badges
1. **Refactor `ProjectCardViewModel` & `ProjectDetailsViewModel`**:
   - Replace hand-rolled initials and pluralizations with calls to `ArabicNameFormatter` and `ArabicProposalParser`.
   - Expose formatted `Budget` and `DeliveryDaysText` via `BudgetFormatter` and `ArabicRelativeTime`.
   - Remove hardcoded hex colors and status strings.
2. **Create `UI/DesignSystem/Badges/EnrichmentBadgeStyle.cs`**:
   - Define authoritative visual states (text, background color, foreground color) using `DesignTokens`.
3. **Fix Silent Notification Binding**:
   - Create `NotificationItemViewModel` wrapping `ProjectSummary` and exposing `PostedRelative`.
   - Wire `RecentNotificationsFlyout.xaml` to the new ViewModel.

### Phase 4: Layout & Cross-Platform Parity
1. **`ProjectCardMobileLayout.xaml`**:
   - Add the skills flex-wrap row (Card Type 3 compliance).
2. **`ProjectDetailsMobileLayout.xaml`**:
   - Add mobile-optimized owner stats section.
   - Remove broken XAML `StringFormat='{0} أيام'` and bind to ViewModel formatted properties.
3. **Update `UNITS.md`**:
   - Register all new formatters, badge styles, and updated layouts.

### Phase 5: Verification & Zero-Regression Check
1. **Build Verification**:
   - `dotnet build MostaqlK.csproj -f net10.0-windows10.0.19041.0 -c Debug` with 0 errors and 0 warnings.
2. **Execute Unit Tests**:
   - Verify all formatting and parsing tests pass.
3. **Theme & Interaction Parity**:
   - Verify light/dark theme parity and RTL Arabic rendering.
