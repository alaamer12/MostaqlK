## Decisions / deviations from the literal prompt (all deliberate, none silent)

1. **`[project.scripts]` points at `mostaql.runtime:cli`, not `:main`.** The prompt demanded
   both `[script] … :main` AND "`async def main(...) -> int`" (frozen §8 signature) AND
   observable behavior "stub returning exit code 1 with a log line". These are mutually
   exclusive: a console-script calling async `main()` returns a coroutine object that never
   executes. `cli()` is the wrapper the prompt itself defines "for console-script use"; it
   propagates the exit code via `SystemExit`. Verified: `uv run mostaql` logs the line and
   exits **1**. Public API `main` is untouched.
2. **`Settings.db_path` / `log_file_path` have `default_factory` defaults.** The literal
   field list (required fields after defaulted ones) is unconstructible as a plain
   dataclass; factories compute exactly the specified defaults. Field names/order/types are
   exact per §8.
3. **Added `diagnostics/__init__.py`** (required to realize deliverable 5b's package) and
   **`__main__.py`** (mandated by frozen plan §7 directory structure; omitted from the
   prompt's skeleton enumeration).
4. **Coverage `fail_under = 60`** for Wave A per deliverable-5c correction (supersedes the
   earlier "=85 harmless" bullet); README documents the raise-to-85 from Wave B. Actual
   current coverage is already 85.28%.
5. **import-linter top-level flag `include_external_packages = true` added** — required by
   the tool itself whenever forbidden modules include externals (`lxml`/`sqlite3`/`httpx`);
   the three contracts match plan §10 exactly and are all KEPT.
6. **Strict boolean parsing** for `MOSTAQL_SAFE_REQUESTS` (accepted tokens error loudly on
   anything else) and **log-level validation** against standard level names — unspecified in
   the prompt; chosen for clear ConfigError messages consistent with the config-error ethos.
7. **`start_paused` has no env var** (TOML/defaults only) — matches the prompt's exact,
   exhaustive env-var list.
